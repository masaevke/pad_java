# ДЗ_05 - API-first проектирование сервиса

## Зачем этот API

API нужен для управления подписчиками Telegram-отчётов Петровича об автопарке: получателями, временем рассылки и состоянием подписки.

## Как делал

Swagger-api написан самостоятельно

За основу взят существующий проект `petrovich_ai`

В контракт включены пять операций:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/subscribers` | Получить список подписчиков |
| GET | `/subscribers/{subscriber_id}` | Получить одного подписчика |
| POST | `/subscribers` | Создать или возобновить подписку |
| PATCH | `/subscribers/{subscriber_id}` | Изменить настройки подписки |
| DELETE | `/subscribers/{subscriber_id}` | Удалить подписку |

Префикс адресов - `/api/v1`. Для операций описаны `summary`, успешные ответы `200` и ошибки с причинами. Для адресов одного подписчика задан параметр `subscriber_id`, для POST и PATCH - тела запросов. GET списка не принимает параметров. DTO запросов и ответов вынесены в `components/schemas`, внутренние модели базы данных в контракт не включены.

Работа выполнена по генерации сервиса выполнена с помощью агента Codex на базе GPT-6 и с применением OpenAPI Generator CLI 7.12.0 с генератором `spring` создал в [service](service) каркас Java/Spring Boot: интерфейс API, контроллер, DTO, настройки и Maven-проект. Точная команда генерации и команды запуска приведены в [GENERATE.md](GENERATE.md).


## Проверка результата

- Спецификация прошла проверку `openapi-spec-validator`
- OpenAPI Generator успешно обработал все пять операций
- Команда Maven `clean verify` завершилась с `BUILD SUCCESS`
- Сгенерированный тест запуска Spring-контекста прошёл: 1 тест, 0 ошибок и 0 падений. Проверка выполнялась на установленной Java 25; целевая версия Java в сгенерированном `pom.xml` - 17

Сервис представляет собой каркас: обработчики возвращают `501 Not Implemented`
